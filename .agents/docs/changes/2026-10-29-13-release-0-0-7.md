# 2026-10-29 · 发布 0.0.7（安装器进程/权限修复）

- **范围**：版本号与发布（full package）
- **触发**：用户要求发布，带上三批安装器修复
- **提交**：working tree

## 源码改动

| 文件 | 类型 | 说明 |
|---|---|---|
| `package.json` / `scripts/npm/package.json` / `scripts/npm/package-lock.json` | 修改 | 版本 0.0.6 → 0.0.7 |

插件 Kotlin 代码与 0.0.6 相同；本次实质内容是 `scripts/npm` 的进程与权限处理
（见 `2026-10-29-11`、`2026-10-29-12`）。

## 为什么改

0.0.6 只解决了 runtime 内置问题。安装流程仍有三个缺陷：

1. `taskkill /IM` 没有 `/T`，只关 IDE 不关子进程；
2. IDE 退出后残留的 ZCode node 进程锁住 `plugins/zcode-ide`，导致删目录/解压失败；
3. IDE 以管理员身份启动时普通终端"拒绝访问"，且没有任何提示。

## 行为变化

- 关闭 IDE 改为树杀；强制结束按 pid 并输出失败原因。
- 安装前清理命令行引用目标插件目录的 node 残留进程；解压遇 `EBUSY/EPERM` 自动清理重试。
- 权限不足时按需弹 UAC，用管理员权限强杀；提权脚本用 `-EncodedCommand` 内联，不落地 .ps1，
  不受 `ExecutionPolicy Restricted` / 组策略限制；脚本排除安装器自身 pid。
- 安装包 49,965,149 bytes（完整包，含 runtime）。

## 验证

- 构建：`node scripts/release.mjs --apply --bundle-runtime` → `zcode-ide-0.0.7.zip`，
  49,965,149 bytes，sha256 `fff7b11ac5cc0b4555bebb15dfdf27c613e880f3baa6e60551bed1d98fb2bcac`，
  含 `runtime/`（5891 个 runtime 条目）与 `lib/zcode-ide-0.0.7.jar`；manifest 签名自检通过。
- 本地安装：`update --zip …0.0.7.zip --target <临时目录> --no-launch` → 5381 个文件，
  `runtime/web/index.html` 存在，安装器提示"完整包，已内置 runtime"。
- 发布：`--apply --skip-build --push --npm --allow-http` 上传 5 个对象（zip 49.9MB / 8.2s），
  npm 发布 `zcode-idea@0.0.7`。
- 远端核验：`/0.0.7/manifest.json` 的 `size`/`sha256` 与本地一致；zip `HEAD` 200，
  `Content-Length=49965149`。
- 单元/集成测试：`scripts/npm` 98 个用例全绿（前两次提交已覆盖）。

## 风险 / 后续

- **国内镜像同步延迟**：本机 `npm config get registry` 指向 `https://registry.npmmirror.com/`，
  发版后镜像只到 0.0.6，`npx zcode-idea@latest` 会看到旧版本甚至报
  `ETARGET No matching version found`（实测）。官方 registry 立即生效：
  `npm view zcode-idea dist-tags --registry https://registry.npmjs.org/` → `latest: 0.0.7`。
  绕过镜像用：
  `npm_config_registry=https://registry.npmjs.org/ npx -y zcode-idea@latest update`
  （PowerShell：`$env:npm_config_registry='https://registry.npmjs.org/'; npx -y zcode-idea@latest update`）。
- 稳定指针仍被七牛域名级缓存影响（本次刷新接口 404 / fetch failed），版本化清单不受影响。
- 分发域名仍是 HTTP 测试域名；正式对外前需换 HTTPS。
- 完整包 47.6MB 是 runtime CDN 未接通期间的取舍，恢复薄包的前提见 `2026-10-29-10`。
