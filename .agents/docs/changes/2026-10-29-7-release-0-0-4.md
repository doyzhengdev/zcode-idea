# 2026-10-29 · 发布 0.0.4（含索引期可用修复）

- **范围**：版本号与发布（`package.json`、`scripts/npm/package.json`、`scripts/npm/package-lock.json`）
- **触发**：用户要求重新打包并发布
- **提交**：working tree

## 源码改动

| 文件 | 类型 | 说明 |
|---|---|---|
| `package.json` | 修改 | `version` 0.0.3 → 0.0.4 |
| `scripts/npm/package.json` | 修改 | 同上（npm 包与插件同一版本） |
| `scripts/npm/package-lock.json` | 修改 | 同步 `version` 与 `packages[""].version` |

## 为什么改

0.0.3 已发布到 npm（同版本不可覆盖），而本次要带上两个代码修复：

- 工具窗与启动活动声明 `DumbAware`，索引期间面板可用（`2026-10-29-5`）；
- 远控自动恢复改为索引结束时补试（`2026-10-29-6`）。

版本号是 `release.mjs` 的单一来源（npm 包 / 插件 / OSS 路径 / manifest 同源），根 `package.json` 必须一致，脚本会硬校验。

## 行为变化

- 安装包版本变为 0.0.4；`stable` 通道指针指向 0.0.4。
- 0.0.3 的用户执行安装器更新会拿到 0.0.4。

## 验证

- `node scripts/release.mjs`（dry-run）：版本一致性通过，计划 5 个对象。
- `node scripts/release.mjs --apply`：构建产物 `zcode-ide-0.0.4.zip`，3,833,367 bytes，sha256 `f98bcf36d586…0355`；manifest 签名通过仓库公钥自检。
- 本地安装验证：`npm pack` 得到 32,649 bytes / 16 文件；`node scripts/npm/bin/zcode-idea.mjs --zip … --target <临时目录> --no-launch` 安装成功，落地 `zcode-ide-0.0.4.jar`。
- 远端发布：`--apply --skip-build --push --npm --allow-http`，5 个对象上传成功，npm 发布 `zcode-idea@0.0.4`。
- 发布后核验：版本化清单 `pluginVersion=0.0.4`、`sha256`/`size` 与本地一致；稳定指针已指向 0.0.4；zip `HEAD` 200 且 `Content-Length=3833367`。

## 风险 / 后续

- 分发域名仍是七牛 **HTTP 测试域名**（`http://tnbe4cmeo.hn-bkt.clouddn.com`，本次用 `--allow-http`），正式对外前需换 HTTPS 域名。
- `manifest.json` / `manifest.sig` 以 `no-cache` 上传，但七牛域名级缓存规则可能覆盖对象头；若更新延迟，需在控制台刷新 CDN。
- npm `0.0.4` 一旦发布不可撤回，后续改动需发 0.0.5。
