# 2026-10-29 · 发布 0.0.5（安装器 update 子命令）

- **范围**：版本号与发布（`package.json`、`scripts/npm/package.json`、`scripts/npm/package-lock.json`）
- **触发**：用户要求发布 0.0.5，把 `update` 子命令交付到 npm
- **提交**：working tree

## 源码改动

| 文件 | 类型 | 说明 |
|---|---|---|
| `package.json` | 修改 | `version` 0.0.4 → 0.0.5 |
| `scripts/npm/package.json` | 修改 | 同上 |
| `scripts/npm/package-lock.json` | 修改 | 同步 `version` 与 `packages[""].version` |

插件 Kotlin 代码与 0.0.4 完全相同；本次发布的实质内容是 `scripts/npm` 的新 CLI（`update` 子命令，见 `2026-10-29-8`）。

## 为什么改

`update` 只在源码/本地可用，npm 版本不可覆盖且安装器按自身版本读 `<version>/manifest.json`，必须发一个新的 npm + 版本化清单 + zip 组合才能让 `npx zcode-idea@latest update` 对用户生效。

## 行为变化

- `npx zcode-idea@latest update` 可用（= `--all --yes --force`）。
- 安装包版本 0.0.5；插件功能与 0.0.4 相同。

## 验证

- `node scripts/release.mjs --apply`：构建 `zcode-ide-0.0.5.zip`，3,833,361 bytes，sha256 `7149499993eacee0c06c8bbddccf6ffaaa340733ebe969f573927bebf1e35939`；manifest 签名自检通过。
- 本地安装验证：`npm pack` 得 `zcode-idea-0.0.5.tgz`（16 文件），`npx --package ./zcode-idea-0.0.5.tgz -- zcode-idea update --zip …0.0.5.zip --target <临时目录> --no-launch` 安装成功，落地 `zcode-ide-0.0.5.jar`。
- 远端：`--apply --skip-build --push --npm --allow-http`，OSS 已上传、npm 已发布 `zcode-idea@0.0.5`。
- 发布后核验：`/0.0.5/manifest.json` 返回 `pluginVersion=0.0.5`，`sha256`/`size` 与本地一致；zip `HEAD` 200 且 `Content-Length=3833361`。

## 风险 / 后续

- **稳定指针（`/stable/manifest.json`）仍返回 0.0.4**：响应头 `Age: 874`、`Last-Modified` 仍是 0.0.4 上传时间，说明七牛域名级缓存规则覆盖了对象的 `no-cache`。版本化清单路径（`/0.0.5/manifest.json`）是权威来源，0.0.4+ 安装器不受影响；只有仍在读稳定指针的旧安装器会滞后，必要时在七牛控制台刷新该 key。
- 分发域名仍是 HTTP 测试域名，正式对外前需换 HTTPS。
