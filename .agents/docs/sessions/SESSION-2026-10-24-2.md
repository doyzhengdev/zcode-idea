## 本会话完成的功能

机制：插件加载 webview 时 URL 追加 `&ideHost=1`（`ZCodePanel.createBrowser`），UI 侧 `packages/ui/src/lib/ideHost.ts` 的 `isIdeHost()` 读参数。

- 隐藏侧栏「自动化」「插件市场」（`ProjectSidebarNavigation.tsx`）；隐藏任务列表头部的搜索/视图切换按钮（`ProjectSidebarListHeader.tsx` `hideActions`）
- 中间只渲染**当前项目**的任务、按最近活动排序（`project-sidebar/index.tsx` 的 `ideHost` 分支：归一化路径匹配项目 roots 后按 `task.projectId` 过滤）；其它项目与无归属散会话不显示
- 隐藏左上角前进/后退箭头，顶部 48px 占位缩为 8px（`DesktopTopOverlay.tsx`、index.tsx）
- 右上角隐藏帮助/终端/右侧面板三按钮，只留 ➕（`WorkspaceHeaderActionSection.tsx`）：新建会话 + 侧栏收起时先展开。注意头部只在有活动任务时渲染（上游 `shouldRenderWorkspaceHeader`），欢迎页无 ➕
- 侧栏右缘垂直中点固定折叠把手（`WorkspaceShellLayout.tsx`，`data-testid="ide-sidebar-toggle"`，`left: max(0px, calc(var(--workspace-sidebar-panel-width) - 11px))`），收起后停在左缘可再展开

### 2. 修复「点新建任务无反应」

根因：`useRootWorkspaceActions.ts` 的 `startNewTaskFromActiveWorkspace` 从活动附件身份推导 `hostId=remote:server:<id>`，走远程导航分支要求 `prepareSession` 返回 `workspaceIdentity`；插件场景只回路径且无 `openRemoteProjectWorkspace` → 抛 `project.remote-navigation-unavailable`，catch 静默（`workspaceActionError` 只 set 不渲染）。

修复：`alreadyAttached`（targetIdentity === 活动附件身份；路径用 `sameWorkspacePath` 归一化比较，Windows 分隔符/大小写差异会漏判 `===`）时跳过远程导航直接 `addTab` + `startDraftInWorkspace`。排查手法：临时塞 toast——这类静默失败在日志和 console 里都看不到。

### 3. IDE 右键发送文件引用到对话框（参考 zcode-jetbrains-plugin 的 SendFileToInputAction）

- 插件侧：`SendToZCodeComposerAction`（ProjectViewPopupMenu/EditorTabPopupMenu/EditorPopupMenu，支持多选与目录）→ `ZCodeIdeService.sendPathsToComposer` → `ZCodePanel.pushToWebview`（页面未加载时面板内排队；面板未创建时暂存服务层，注册后取走）
- 通道（Java→JS 新方向）：`executeJavaScript("window.__zcodeIdeMessage(<json>)")`，与 JS→Java 的 `window.__ZCODE_IDE_QUERY__` 相对
- Web 侧 `packages/web-ide/src/ideContextPush.ts`：`{op:"filesToInput", refs:[{path,kind}]}` → 每个路径转文件 mention（`buildFileMentionMarkdown`，label=basename）→ **倒序逐条** `requestComposerTextInsert(..., "prepend-if-missing")`，间隔 80ms（插入请求是单槽状态，同轮发多条只留最后一条）
- 配套放开：`SessionPane` 的 `externalTextInsertRequest` 从仅草稿态改为 `focused` 即可（活动会话也能插入；桌面端既有调用只在草稿态触发，不受影响）

### 4. 会话文件点击 → IDE 编辑器打开

- 拦截点：`App.tsx` `handleOpenCodeViewerIfWritable`（改动摘要行、预览卡）；消息/工具行的文件链接经 `WorkspaceShellLayout.handleOpenMarkdownFileLink`（stat 为文件后）落到同一入口 → `platform.openExternalFile` → 桥 → `FileEditorManager.openFile`
- **已修的坑**：消息链接是 `./a/b` 或含 `..` 的相对路径，直接拼接交给 IDE 会解析失败且静默。现在 `App.tsx` `normalizeIdeFilePath` 按段消解 `.`/`..`；Kotlin `File(path).canonicalFile` 兜底；VFS 找不到时弹「未能打开文件」通知，不再无声
