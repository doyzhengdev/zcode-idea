# 会话纪要 2026-10-24-5：多窗口共享单一 ZCode server

## 背景与目标

原架构每个项目窗口各起一套 `@zcode/server`（+ 各自 agent），开 N 个窗口就有 N 个 Node server 进程，内存浪费明显。事实上官方 server 本身就是多项目的：任务表主键 `(workspace_key, task_id)`、workspace 是**每次 RPC 携带**的参数而非 server 状态、agent 进程池按 workspaceKey 各自 spawn（`zcodeAgentProcessManager.ts` 的 `processesByWorkspaceKey`）——桌面客户端就是单进程多项目形态。

目标：全 IDE 共用一个 server，前端入口 URL 携带项目路径（`ideWorkspace`）区分各窗口的项目。插件形态与官方客户端的唯一差别：客户端侧栏显示所有项目，插件按窗口锁定当前项目（`isIdeHost()` 门控的 `project-sidebar` 已实现该过滤）。

## 方案三轮分析的关键修正

1. **停服模型**：不随项目窗口停（PROJECT 级 service 懒创建，从未开过面板的窗口没有 dispose，"最后一个项目关闭停 server"会漏判泄漏进程）。server 绑定 IDE 生命周期：首面板懒启动，`ZCodeServerManager.dispose()`（应用级）收尾；关光所有项目常驻，重开秒连，与 LSP 类常驻服务一致。
2. **不做 PID 治理**：曾考虑"记录 PID + tasklist/ps 验证映像 + 杀掉残留重建"，平台相关代码与误杀风险不成比例。降级为：token 持久化（`zcode.ide.server.token`）+ 端口被占时带 token probe `/api/server-info`，200 则是自家残留→直接复用并 WARN（更新 runtime 后需重启机器或手动结束 node 才生效）；非 200 → 换随机端口。
3. **EDT 线程纪律**：`manager.url()` 持锁可达数分钟（Node 下载）。重试按钮在 EDT 直接调 `restart()`/`isAlive()` 会抢锁冻结 UI。重试整体放 pooled thread：server 活→只重建本窗口；server 死→`restart()`（后台）+ 广播重载所有窗口。
4. **浏览器防重入**：reload 广播与进行中的启动流程并发会泄漏 JBCefBrowser。`setupBrowser` 开头先 `teardownBrowser()`（dispose 旧 query/browser、复位 pageLoaded）。
5. **端口迁移**：全局端口 key `zcode.ide.server.port`（原按工作区哈希）。首次升级用 `migrateLegacyPort` 沿用最先启动窗口的旧端口——**只能保住一个**，各项目旧端口是不同 origin，无法合并；其余项目 localStorage 丢一次。
6. **`ZCODE_SERVER_WORKSPACE`**：server 不再绑定项目，注入 `user.home` 作 `/api/server-info` 默认展示；entry-http 的 legacy 数据修复以它跑一次性幂等修复，无害。

## 行为变化

- 多窗口 = 1 个 server 进程 + 按 workspace 各一个 agent；省 (N−1) 个 server 进程。JCEF renderer 每窗口一份不可省——内存下降是真的，但不是"多窗口几乎不占内存"。
- 所有窗口同 origin：localStorage 偏好类 key（侧栏宽度、界面模式等）跨窗口共享——表现为"更一致"，非 bug；官方前端无 BroadcastChannel、zustand store 纯内存每页独立，无跨窗口状态联动。
- 同一项目开两个窗口：共享同一 workspaceKey 与同一个 agent 进程，原"端口漂移 bug"自然消失。
- server 重启（重试按钮死分支）会重载**所有**窗口的面板；server 活时重试只重建本窗口。
- 不变量 5 仍适用：不要与桌面客户端同时跑（共享 `~/.zcode`）。

## 已知边界

- 第二个窗口在首个窗口下载 Node 期间阻塞在 manager 锁上，无进度显示（首装场景，一次性）。
- 前端 `connectViaWebSocket` 的 `onClose` 为空：server 重启后，未收到 reload 广播的窗口页面会假死（广播正常时应全覆盖）。
- IDE 异常退出后残留 server：token 匹配则复用旧进程（旧 runtime 版本），更新 runtime 后需重启机器或手动结束 node；token 不匹配（旧版本插件留下的）→ 换端口，localStorage 丢一次。
- 端口迁移只保最先启动窗口的 localStorage。
- 同项目双窗口同时首次引导 `bindWorkspaceProject` 有低概率重复建项目（readTree/saveProject 竞态），未处理。
- `allowOpenWorkspace=true` 保留了"打开工作区"入口，ideHost 门控下是否隐藏未验证。
