# 会话纪要 2026-10-24（四）：归档失败排查与历史 workspace_key 修复

## 现象

点击侧栏任务的「归档」按钮，UI 弹出「归档任务失败」（`taskList.archiveFailed`）。

## 根因

`migrate-tasks-to-local.cjs` 把 `remote:server:<host>` 的会话并入 `local` 时，只更新了
`host_id` / `workspace_identity` / `project_id` / `root_path`，**没有同步 `workspace_key` 和 `workspace_path`**。

`taskIndexRepo` 的主键与全部读写都以 `workspace_key` 为准：

```sql
PRIMARY KEY (workspace_key, task_id)
```

而侧栏列表是按 `project_id` join 出来的，所以这些任务「看得见、点不动」：

- `zcode-task.archiveTask` → `getTaskRow({ workspacePath: 'E:\work\zcode-ide' })` → 查 `workspace_key='E:\work\zcode-ide'` 的行 → 命中不到 → 抛 `task index 中不存在 task: <id>` → 归档失败
- 同一通路的 `setTaskUnread` 在 idea.log 里留下了明确证据
- CLI syncer 按新路径写入时还会撞 `idx_tasks_host_task UNIQUE(host_id, task_id)`

修复前库内遗留：

| workspace_key | 行数 |
|---|---|
| `remote:server:<host>:/E:/github/zcode-ide` | 69 |
| `E:\work\zcode-ide` | 20 |
| `remote:server:<host>:/E:/work/ezllm` | 3 |

## 修复

新增 `scripts/fix-task-workspace-keys.cjs`（`--dry-run` / `--apply`，自动备份到 `~/.zcode/backup/`）：

- `tasks`：旧键 → 当前键，同时把 `workspace_path` 归一
- `task_group_admissions` / `task_group_members`：同步主键，目标键已有登记时丢弃旧登记
- `task_group_view_node_orders`：`node_key` 里的 workspace key 一并替换

实测结果：92 条任务、13 条登记、13 条排序迁移，10 条重复登记丢弃；库内 `remote:%` 键归零。

`migrate-tasks-to-local.cjs` 也补上了 key 归一，避免换机器重跑时再次留下同类脏数据。

## 第二个根因：window-controller 通道不存在

数据修好后归档仍然失败，日志给出明确信号：

```
Unknown channel: window-controller
```

链路：`TaskGroupedView` / `useProjectTaskActions` / `useArchiveManagement` 都从 `useBaseWorkspaceServices()`
取 `windowControllerService`；`RemoteServiceAccess`（`@zcode/client`）**无条件**为它创建 RPC 代理。
但这个通道只有 Electron 桌面主进程注册（`packages/desktop/src/host/index.ts:2590`），独立 server 从不注册。

代理对象本身 truthy，UI 的 `controller ? ... : ...` 判断因此走错分支：归档发出
`controller.mutateTask` → `Unknown channel` → toast「归档任务失败」；而标记已读等命令走
`zcodeTaskService`，所以看起来"只有归档坏"。

修复：`packages/web-ide/src/main.tsx` 用 Proxy 包装 `connectViaWebSocket()` 的返回值，
对 `windowControllerService` 返回 `undefined`，让任务命令统一回落到本地 `zcodeTaskService`
（IDE 单窗口形态本来也没有多窗口 Host 语义）。

## 实测验证（2026-10-24 10:37）

重启 IDE 后通过 JCEF 的 CDP 端口（`jcef_cache/DevToolsActivePort`，此前文档记录"不可用"，
本次实测 `http://127.0.0.1:<port>/json/list` 可正常连接）在真实页面上右键任务行 → 归档任务：

- `idea.log`：`rpc:call] zcode-task.archiveTask OK (1.7ms)`
- 重启后 `Unknown channel` 计数为 0
- 任务行从侧栏消失，`tasks` 表中该行 `archived=1`

## 注意

- 修复直接写 SQLite，IDE 里已加载的任务列表仍是旧内存对象；**重启 IDE / 切换项目刷新列表**后归档才走新 key。
- 与桌面客户端同身份运行时的 SQLite 写锁风险依旧，修复脚本已设 `busy_timeout=15000`。
- 前端改动只重建 `packages/web-ide` 即可；开发期 runtime 优先 `vendor/ZCode` 源码 dist，不需要重跑 `build-runtime.mjs`。
- 日志里仍有独立的 `marketing-touch.query` ZodError（缺少查询参数），与归档无关，未处理。
