## 一、已确认并修复的核心 bug：Windows 盘符翻倍（E:\E:\）

**现象**：插件里问"当前项目目录是什么"，agent 答 `E:\E:\work\ezllm`；同时伴随误报"不是 git 仓库"、子进程报"bash.exe 找不到"。

**根因链**（日志证据：`C:\Users\<user>\.zcode\cli\log\zcode-2026-10-24.jsonl` 第 4267 行）：

1. 插件注入 `ZCODE_SERVER_WORKSPACE=E:\work\ezllm`（正确，无拼接）；
2. server 端 `buildServerRemoteWorkspaceIdentity` → `normalizeWorkspacePathForIdentity`（`packages/shared/src/remote-workspace-identity.ts:39`）为 POSIX 远端设计，无条件加前导 `/` → identity 变 `remote:server:<host>:/E:/work/ezllm`；
3. 会话创建时 `parseRemoteWorkspaceIdentity` 还原出 `/E:/work/ezllm` 当工作目录（UI 只传 identity，agent 端 `resolveWorkspaceRefFromId` 展开，见 `apps/zcode-cli/packages/bootstrap/src/zcode-protocol/workspace.ts`）；
4. agent cwd 在 E 盘，Windows 把"有根无盘符"路径拼到当前盘符 → `E:\E:\work\ezllm`（`path.win32.resolve` 实测复现）。

**官方桌面端为何无此问题**：本地会话不走 identity（`v4-bridge.ts:1255` 注释：本地 pane = 本地路径，identity 只用于远程 pane）；`remote:server` 场景官方假设 server 在 Linux。我们的拓扑（本机 Windows server + agent 同机）首次让 Windows 路径走完 identity 往返。

**修复**（ZCode fork ide-integration 分支，**部分未提交**）：

- `packages/shared/src/remote-workspace-identity.ts`：parse 端新增 `restoreWindowsDrivePathFromIdentity`（`/^\/[A-Za-z]:(\/|$)/` 剥前导斜杠），identity 键不变（`build(parse(x))===x` 恒等，存量 DB 键不漂移）；同步修 `remoteHostIdFromWorkspaceIdentity` 尾段裁剪长度；
- `apps/zcode-cli/packages/core/src/runtime/helpers/persisted-remote-session-path-repair.ts`：`/E:/x` 残留列为可修复污染，旧会话自愈；
- 测试：`packages/shared/test/remoteWorkspaceIdentity.test.ts`（+2 用例）、`persisted-remote-session-path-repair.test.ts`（+1 用例），相关回归全绿；
- 产物已重建（server dist / web-ide dist / zcode.cjs）并重组进插件 `dist/`。
- **实机验证尚未做**：部署新包后在插件里问"当前项目目录是什么"，期望答 `E:\work\ezllm` 且无 bash 报错。

## 二、仓库拓扑决策（已确认）

**独立插件仓库（E:\work\zcode-ide）+ junction 链接 ZCode fork（E:\work\ZCode，分支 ide-integration）**，不并入 ZCode 仓库。理由：fork 职责=最小补丁跟随上游；插件仓库=产品（文档/版本/发布）；runtime 与 fork 快照的绑定要显式管理；补丁未来可上游化（identity 修复是 PR 候选）。

**GitHub 同类项目调研结论**（详见记忆 zcode-embedding-projects）：JetBrains 侧有 leitong666pix-bit/zcode-intellij-plugin（自建 Swing UI + app-server 协议）、william0wang/zcode-acp（74★ ACP 桥）、csuftt（JCEF+DOM 注入）；VSCode 侧多个"复用官方内核"前端；**无人走我们"官方 UI 源码重建 + 自带运行时分发"的路线**。

## 三、目录重构（已完成，改动已暂存、未 commit）

扁平单模块 + runtime→dist + vendor 迁移，全部验证通过（buildPlugin 22s，zip 结构不变：内层 `zcode-ide/` + `lib/` + `runtime/`）：

```
E:\work\zcode-ide\
├── src/main/...              # 源码上移到根（git mv，历史保留）
├── build.gradle.kts          # 根=模块；含 idea{module{excludeDirs}}：
```

同步清理：`.gitignore` 死规则、`RuntimeLayout.kt` 的 `intellij-plugin` 遗留候选、README/HANDOFF/SKILL 全部路径。

**缓存目录结论**：`.gradle`/`.kotlin`/`.intellijPlatform` 无法收敛（各有工具规则，IDEA sync 不认 `--project-cache-dir`），只能靠 excludeDirs 排除 + gitignore。

**遗留陷阱（已知，未消除）**：开着本工程测插件时 `RuntimeLayout` 仍优先选 `vendor/ZCode` 源码 dist 而非打包 runtime（SKILL.md 排错项已更新路径）；`web=` 日志路径以此判断。
